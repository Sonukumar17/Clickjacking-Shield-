How UI Redressing Works

In a clickjacking attack, the adversary embeds a legitimate application into a transparent or hidden iframe (opacity: 0 or z-index: 9999). The attacker layers enticing graphic elements ("Play Video", "Claim Gift", "Close Ad") directly above sensitive buttons on the victim application (e.g. "Transfer Funds", "Delete Account", "Authorize OAuth").

When the victim clicks what appears to be an innocuous decoy button, the click actually registers on the underlying framed application, triggering an unintended state change with the victim's authenticated session!

How Anti-Framing Headers Defeat It

When the protected server responds with Content-Security-Policy: frame-ancestors 'none' or X-Frame-Options: DENY, the client browser enforces this directive before rendering.

The browser abruptly aborts framing, replaces the frame content with a blank error or block screen, and prevents the attacker from rendering or aligning any elements. The attack vector is completely neutralized!
