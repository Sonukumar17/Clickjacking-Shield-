About the ClickjackShield Platform

An advanced cybersecurity platform dedicated to evaluating HTTP anti-framing mechanisms, educating security engineers, and promoting defensive standards against UI redressing vulnerabilities.

Project Objective & Scope

Clickjacking (UI Redressing) is a covert technique where an adversary deceives a victim into clicking on actionable elements within an invisible or obscured frame. By redressing genuine controls, the attacker triggers unintended actions such as funds transfer, credential alteration, or permission escalation within the victim's authenticated session.

The ClickjackShield project was developed to provide an end-to-end educational and diagnostic suite that:

  • Performs rigorous, non-intrusive HTTP security header auditing.
  • Accurately parses and models Content-Security-Policy: frame-ancestors and X-Frame-Options.
  • Distinguishes defensive configuration deficiencies from confirmed exploitation.
  • Provides a strictly sandboxed local demonstration laboratory for safe visual learning.
  • Empowers developers with copy-paste remediation configurations for major production runtimes.

Built-in Defensive Engineering

The scanner engine itself is engineered under strict defensive development principles:

SSRF Immunity: DNS pre-resolution inspects all IP addresses, strictly blocking loopback (127.0.0.1), RFC 1918 private subnets, link-local addresses, and cloud metadata endpoints (169.254.169.254).
Revalidated Redirects: Every redirect hop is followed individually up to a maximum depth of 5, re-verifying SSRF boundaries on each hop.
HTTPS Enforcement: Restricted to public TLS-secured endpoints to prevent man-in-the-middle manipulation of security headers.
Resource Boundaries: Response size caps (512 KB), aggressive socket timeouts (6s), and sliding-window rate limiting defend against denial-of-service.
Ethical Use & Responsible Disclosure

This application is designed exclusively for educational purposes, ethical security audits, and authorized penetration testing. Users must assess only applications they own or have received formal authorization to test. Do not perform security assessments against unauthorized infrastructure.
