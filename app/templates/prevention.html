OWASP & W3C Defensive Engineering Guide

Clickjacking Prevention & Remediation

Implement definitive anti-framing defenses using Content-Security-Policy (CSP) Level 3 and X-Frame-Options across major web servers, cloud gateways, and backend web application frameworks.

W3C Recommendation

1. Content-Security-Policy: frame-ancestors

The frame-ancestors directive within the Content-Security-Policy HTTP response header is the official modern standard for controlling which parent origins are authorized to embed a web resource within <iframe>, <frame>, <embed>, or <object> tags.

Disallow All Framing (Recommended Default):
Content-Security-Policy: frame-ancestors 'none';
This prevents the protected page from being embedded by any origin (including the site's own origin) when the policy is enforced by modern browsers.
Allow Same-Origin Embedding Only:
Content-Security-Policy: frame-ancestors 'self';
Permits framing only if the top-level parent page matches the exact scheme, hostname, and port of the resource.
Allow Specific Trusted Third-Party Origins:
Content-Security-Policy: frame-ancestors 'self' https://trusted-partner.example.com https://*.corp.example.com;
Allows explicit trusted domains to embed the page while rejecting all unauthorized cross-origin attempts.
RFC 7034

2. X-Frame-Options (Legacy Fallback)

The X-Frame-Options header was introduced by Microsoft in Internet Explorer 8 and documented in RFC 7034. While superseded by CSP Level 2/3, it remains vital as a defense-in-depth fallback for legacy browsers.

Strict Denial:
X-Frame-Options: DENY
Prevents framing completely in all browsers that support the directive, even when requested by a page on the same origin.
Same-Origin Framing:
X-Frame-Options: SAMEORIGIN
Allows framing only if the parent window originates from the identical origin.
Deprecation Notice: Avoid using X-Frame-Options: ALLOW-FROM <uri>. It is deprecated, unsupported in Chrome and Safari, and will leave applications completely unprotected. Use CSP frame-ancestors instead.

Key Architectural Distinction: frame-ancestors vs. frame-src

frame-ancestors (Defends THIS page)

Answers: "Who is allowed to embed this page as an iframe?"

  • Controls framing of the current document by other parent origins.
  • Primary clickjacking defense.
  • Inherited by child frames under CSP Level 3.
frame-src / child-src (Restricts EXTERNAL iframes)

Answers: "What URLs can this page embed inside itself?"

  • Controls what child iframes your page is permitted to embed.
  • Defends against Cross-Site Scripting (XSS) and rogue iframes.
  • Does NOT prevent this page from being framed by attackers!

Implementation Guidance Across Platforms

In Python Flask, apply headers globally using an after_request hook or Flask-Talisman:

# Option 1: Native Flask after_request hook
@app.after_request
def set_anti_framing_headers(response):
    response.headers["Content-Security-Policy"] = "frame-ancestors 'none';"
    response.headers["X-Frame-Options"] = "DENY"
    return response

# Option 2: Using Flask-Talisman extension
from flask_talisman import Talisman

csp = {
    'default-src': '\'self\'',
    'frame-ancestors': '\'none\'',
}
Talisman(app, content_security_policy=csp, frame_options='DENY')

In your Nginx server or location configuration block, use the always flag so headers are sent on all status codes:

# Add to /etc/nginx/conf.d/security.conf or inside server {} block
add_header Content-Security-Policy "frame-ancestors 'none';" always;
add_header X-Frame-Options "DENY" always;

# Optional: Add SameSite cookie defaults and MIME defense
add_header X-Content-Type-Options "nosniff" always;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;

In Apache httpd.conf, ssl.conf, or .htaccess (requires mod_headers):

<IfModule mod_headers.c>
    Header always set Content-Security-Policy "frame-ancestors 'none';"
    Header always set X-Frame-Options "DENY"
    Header always set X-Content-Type-Options "nosniff"
</IfModule>

In Node.js with Express, utilize the popular helmet security middleware:

const express = require('express');
const helmet = require('helmet');
const app = express();

app.use(
  helmet({
    contentSecurityPolicy: {
      directives: {
        defaultSrc: ["'self'"],
        frameAncestors: ["'none'"], // or ["'self'"]
      },
    },
    frameguard: {
      action: 'deny', // sets X-Frame-Options: DENY
    },
  })
);

In Django settings.py with django-csp:

# settings.py
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'django.middleware.clickjacking.XFrameOptionsMiddleware',
    'csp.middleware.CSPMiddleware',
    # ...
]

# Configure X-Frame-Options
X_FRAME_OPTIONS = 'DENY'

# Configure CSP frame-ancestors via django-csp
CSP_FRAME_ANCESTORS = ("'none'",)

Verification & Automated Testing

After applying configurations, verify compliance using terminal tools or automated CI/CD security linters:

1. Verify with cURL:
curl -I -s https://your-domain.example.com | grep -Ei "(content-security-policy|x-frame-options)"
2. Automated CI/CD Regression Test (Python pytest):
def test_anti_framing_headers(client):
    response = client.get("/")
    assert response.headers.get("X-Frame-Options") == "DENY"
    csp = response.headers.get("Content-Security-Policy", "")
    assert "frame-ancestors 'none'" in csp
SameSite Cookie Defense

In addition to anti-framing headers, setting SameSite=Lax or SameSite=Strict on all session cookies provides a secondary barrier against authenticated clickjacking:

Set-Cookie: sessionid=...; Secure; HttpOnly; SameSite=Lax
When an attacker embeds a page into a cross-site iframe, modern browsers will withhold SameSite cookies, ensuring any framed action executes as an unauthenticated anonymous user.
Hardening Checklist
  • Serve Content-Security-Policy: frame-ancestors 'none' globally.
  • Serve X-Frame-Options: DENY for legacy browser support.
  • Enforce SameSite=Lax or Strict on session cookies.
  • Apply anti-framing headers to error pages (404, 500) and redirect responses.
  • Avoid deprecated directives like ALLOW-FROM.
