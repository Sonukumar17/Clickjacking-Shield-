1. Project Executive Summary

The Student Portfolio & Project Management System is an enterprise-grade, modern web application developed with PHP 8.2 and Bootstrap 5. It combines an elegant, responsive public-facing portfolio showcasing technical skills, academic background, and selected engineering builds with a secure administrative Content Management System (CMS) that supports full CRUD operations over portfolio data.

Designed according to modern software architecture principles, it incorporates strict input validation, CSRF mitigation, session isolation, and a modular Repository Factory pattern supporting interchangeable storage backends (File-based JSON, MySQL, and MongoDB).

2. Architectural Design & Design Patterns

2.1 The Repository Factory Pattern

The application decouples business logic, validation, and presentation from the persistence layer using the Repository Design Pattern. A centralized RepositoryFactory inspects the environment configuration (DB_DRIVER) and instantiates the appropriate concrete repository implementation:

  • File Driver (Default): Zero-setup JSON document store (storage/database.json) with thread-safe file locking. Ideal for standalone local execution and lightweight containerized deployments.
  • MySQL Driver: Relational storage using PDO prepared statements, foreign key constraints, and normalized tables.
  • MongoDB Driver: Document-based NoSQL storage utilizing typed BSON ObjectIDs and schema indexing.

2.2 Front-Controller Routing & Asset Delivery

The custom router (router.php) serves as the local development and container front-controller. It resolves static resources (/assets/, /uploads/) with explicit RFC-compliant MIME types (e.g., text/css, application/javascript, image/webp), eliminating MIME-type sniffing conflicts in modern browsers. It also handles administrative directory redirects (/admin → /admin/dashboard.php) and clean URL routing.

4. Security Architecture & Robustness

  • CSRF Mitigation: Every state-changing form incorporates a cryptographically secure random token validated via verify_csrf() before request processing.
  • XSS Prevention: Output rendering is systematically passed through the e() helper invoking htmlspecialchars() with ENT_QUOTES and UTF-8 encoding.
  • Upload Hardening: Uploads undergo finfo MIME-type verification (JPEG, PNG, WEBP), file size enforcement (max 2MB), and random hex renaming to prevent directory traversal or remote script execution.
  • Credential Storage: Credentials are encrypted using PHP's standard password_hash() with PASSWORD_BCRYPT.
  • Session Security: Admin routes invoke require_admin() enforcing authenticated session existence, HttpOnly cookies, and Lax SameSite policy.
